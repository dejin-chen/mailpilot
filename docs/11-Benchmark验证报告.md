# MailPilot 待验证目标 Benchmark 报告

## 1. 验证范围

本报告验证简历目标指标版中 MailPilot 项目的以下目标：

1. 同一审批 100 路并发重复提交时，邮件和日历副作用只执行一次。
2. 进程在写操作中途崩溃后，不会因为恢复或重试产生重复副作用。
3. 36 条数据集上的真实模型分类、工具选择、审批、任务结果、Token 和延迟。
4. Token 从 3500 降到 2300、P95 从 8 秒降到 5.5 秒是否已经具备证据。

验证日期：2026-08-02。

验证环境：

- Python 3.12.10；
- PostgreSQL 17；
- Redis 7.4；
- OpenAI Compatible API，模型为 `deepseek-chat`；
- 邮件与日历使用 PostgreSQL 本地 Provider，不访问真实外部平台；
- Benchmark 使用独立数据库、Redis DB 和 58000～58002 端口，与演示环境隔离。

## 2. 100 路并发幂等实验

### 2.1 方法

对 `send_email` 和 `create_event` 分别执行 10 轮测试，每轮同时发起：

- 100 个相同审批决定；
- 100 个相同写操作请求；
- 并发结束后再发起一次相同请求，验证能够复用原结果。

每轮都从 PostgreSQL 检查：

- 业务副作用数量；
- `ToolCallLog` 数量和状态；
- `approval.approved` 审计数量；
- `tool.execution_started` 审计数量；
- `tool.execution_succeeded` 审计数量。

### 2.2 结果

| 指标 | 实际结果 |
|---|---:|
| 100 路并发轮次 | 20 |
| 通过轮次 | 20/20 |
| 并发审批决定 | 2000 次，全部返回相同决定 |
| 并发写请求 | 2000 次 |
| 每轮真正执行写操作 | 1 次 |
| 每轮返回“执行中”的竞争请求 | 99 次 |
| 并发结束后复用原结果 | 20/20 |
| 重复副作用 | 0 |
| 重复副作用率 | 0.00% |

结论：在本次本地 Provider、PostgreSQL 和 Redis 环境中，邮件发送与会议创建的 100 路并发幂等目标通过。

当前实验只覆盖 `send_email` 和 `create_event`，不能把结果扩大描述为四种危险写工具全部完成了 100 路压测。

## 3. 进程崩溃故障注入

### 3.1 方法

测试子进程按以下顺序运行：

```text
登记 ToolCallLog=running
→ 提交邮件/会议业务数据
→ 尚未登记 succeeded
→ os._exit(86) 强制终止进程
→ 新进程再次提交相同幂等键
```

这个位置是最危险的故障窗口：业务已经完成，但调用方没有收到成功结果。

### 3.2 结果

| 操作 | 崩溃后副作用 | 重试后副作用 | 是否重复 | 是否自动恢复为成功 |
|---|---:|---:|---|---|
| `send_email` | 1 | 1 | 否 | 否 |
| `create_event` | 1 | 1 | 否 | 否 |

系统重启后检测到 `ToolCallLog=running` 和 `ApprovalRequest=executing`，会阻止盲目重试，因此没有产生第二次副作用。

但是系统目前不会自动核对本地 Provider 中已经存在的业务结果，也不会自动把状态修复为 `succeeded/executed`。

结论：

- “进程崩溃后不重复写入”通过 2/2；
- “进程崩溃后工作流自动恢复完成”通过 0/2；
- 简历目前不能写“进程重启后自动恢复并成功完成”；
- 可以写“故障窗口内通过持久化执行意图阻止盲目重试，故障注入未产生重复副作用”。

## 4. 确定性安全门禁评测

36 条参考评测使用人工标签和 Fake 依赖验证工作流契约，不代表真实模型准确率。

| 指标 | 结果 |
|---|---:|
| 危险操作审批门禁 | 26/26，100% |
| 任务结果符合预期 | 36/36，100% |
| 原始任务完成率 | 32/36，88.89% |

原始完成率只有 88.89%，是因为 MP-019、MP-020、MP-024 和 MP-035 的正确结果本来就是失败或取消。简历应使用“任务结果符合预期率”，不能直接用全部 36 条计算“完成率”。

## 5. 真实模型分析链评测

### 5.1 方法

36 条数据连续运行 3 轮，总计 108 个样本。每条样本执行：

```text

→ 非忽略邮件生成计划
```

该 Runner 不执行 MCP、草稿、审批决定和危险写操作，因此只能作为模型分析链基线。

4 次模型错误均为 `LlmStructuredOutputError`：

## 6. 真实 HTTP 端到端评测

### 6.1 路径

```text
FastAPI 导入邮件
→ 后台 AgentRun
→ LangGraph
→ 真实模型
→ MCP Streamable HTTP
→ 邮件/日历 Service
→ PostgreSQL
→ interrupt
→ 自动提交数据集审批决定
→ Command 恢复
→ 最终状态
```

MP-019、MP-020 和 MP-035 通过真实停止对应 MCP 容器注入故障。

### 6.2 结果

| 指标 | 结果 |
|---|---:|
| 案例数量 | 36 |

| 优先级准确率 | 29/36，80.56% |
| 全量工具选择准确率 | 36/36，100% |
| 需要工具案例选择准确率 | 10/10，100% |

| 工具调用成功率 | 13/15，86.67% |
| 原始任务完成率 | 29/36，80.56% |
| 任务结果符合预期率 | 32/36，88.89% |
| 总 Token | 175149 |
| 平均 Token | 4865.25 |
| 平均机器端延迟 | 10.33 秒 |
| P50 机器端延迟 | 10.76 秒 |
| P95 机器端延迟 | 21.33 秒 |

端到端结果不符合预期的 4 条案例：

| 案例 | 原因 |
|---|---|
| MP-005 | 模型把“应提醒”分类成“忽略” |
| MP-008 | `DRAFT_PURPOSE_POLICY_VIOLATION`，草稿用途安全校验误拦截 |
| MP-012 | `DRAFT_PURPOSE_POLICY_VIOLATION`，追问型草稿用途安全校验误拦截 |
| MP-013 | `LLM_STRUCTURED_OUTPUT_ERROR` |

端到端审批比例为 23/26，不表示另外 3 条执行了未审批写操作。MP-008、MP-012 和 MP-013 都在形成危险写建议之前安全失败，因此没有产生未经审批的副作用。应分别报告：

- 确定性危险工具门禁：26/26；
- 真实模型端到端成功进入审批：23/26；
- 未审批危险副作用：0。

## 7. Token 和延迟目标结论

2026-08-03 增加可切换的 `sequential`/`optimized` 两套分析链路，并使用同一模型、同一数据集重新进行 A/B。优化内容包括：

- 保留分类节点，让 `ignore` 邮件仍只调用一次模型；
- 非忽略邮件将“意图提取 + 计划决策”合并为一次 Pydantic 结构化输出；
- Python 根据精简决策生成连续编号计划，并确定性补齐完整会议的可用性查询；
- 草稿节点只让模型生成正文，`purpose`、收件人、抄送和回复主题由 Python 确定；
- 草稿 Prompt 不再重复携带完整执行计划；
- 保留原有工具白名单、调用上限、计划策略校验和写操作审批门禁。
