# MailPilot Token 与 P95 延迟优化报告

## 1. 问题与目标

优化前，一封需要回复的普通邮件通常需要依次执行：

```text
分类模型 → 意图模型 → 计划模型 → 草稿模型
```

前三个节点串行运行；邮件正文会在意图、计划和草稿 Prompt 中重复出现，计划节点还会再次接收完整分类和意图。主要瓶颈不是 Python 或数据库，而是重复 Token 和多一次模型网络往返。

本次目标是降低平均 Token 和 P95 延迟，同时保持或提高分类、工具选择、审批拦截和任务结果指标。

## 2. 实施方法

### 2.1 保留分类，合并非忽略邮件的后续分析

分类节点继续独立存在，`ignore` 邮件仍只调用一次模型并立即结束。非忽略邮件把“意图提取”和“计划决策”合并为一次 `IntentPlanDecision` 结构化输出。

优化前非忽略邮件分析需要 3 次模型调用，优化后需要 2 次；需要回复并生成草稿的常见完整路径由 4 次降为 3 次。

### 2.2 模型做语义判断，Python 做确定性编排

模型输出邮件意图、只读工具选择和是否生成草稿。Python 再完成以下工作：

- 生成连续编号的 `ExecutionPlan`；
- 对完整会议使用已经校验的开始和结束时间构造 `check_availability`；
- 时间不完整时移除猜测出的日历调用并生成澄清步骤；
- `reply` 和需要澄清的邮件必须生成草稿；
- 继续执行工具白名单、资源范围、调用次数和时间一致性校验。

这减少了模型输出的自然语言计划字段，也避免模型二次抄写时间产生偏差。

### 2.3 草稿信封确定性生成

模型只生成 `body_text`。以下字段由 Python 根据可信状态生成：

- `purpose`：由分类和 `needs_clarification` 决定；
- `recipients`：固定为原始发件人；
- `cc`：固定为空；
- `subject`：根据原主题生成回复主题。

构造后仍运行原有草稿安全策略校验。该方法缩小了结构化输出 Schema，消除了模型填写错误用途或扩大收件人范围的机会。

### 2.4 可回退配置

环境变量 `AGENT_ANALYSIS_MODE` 支持：

- `optimized`：默认优化链路；
- `sequential`：原始三段分析链路，用于回归和 A/B。

## 3. 测试方法

测试环境：Python 3.12.10、PostgreSQL 17、Redis 7.4、`deepseek-chat` OpenAI Compatible API。

两种口径：

1. 分析链：36 条版本化数据集各运行 3 轮，优化前后各 108 个样本；顺序执行，避免并发限流污染单请求延迟。
2. 完整 E2E：优化前后各 36 条，包含 FastAPI、LangGraph、真实模型、MCP Streamable HTTP、Service、PostgreSQL、Redis、审批暂停与恢复，并对 MCP 注入故障。

P95 使用同一报告中的全部样本计算，没有排除失败或慢请求。模型服务网络状态会影响绝对延迟，因此对外引用时必须同时说明模型、数据量和测试口径。

## 5. 结果摘要与适用口径

分析链结果：

> 针对邮件 Agent 串行模型调用和重复上下文瓶颈，将“意图提取 + 计划决策”合并为单次 Pydantic 结构化调用，并用 Python 确定性生成执行计划与草稿信封；在 DeepSeek Chat、36 条数据集 × 3 轮的 108 样本 A/B 中，将平均 Token 从 3992 降至 3154（下降 21.0%），P95 延迟从 12.84 秒降至 10.68 秒（下降 16.8%），工具正样本选择与危险意图审批判定均达到 100%。

系统级结果：

> 在包含 FastAPI、LangGraph、MCP、PostgreSQL、Redis 和人工审批恢复的 36 条完整 E2E 中，将平均 Token 从 4865 降至 3857（下降 20.7%），P95 从 21.33 秒降至 12.14 秒（下降 43.1%），任务结果符合预期率由 88.89% 提升至 97.22%。

不得将“P95 已达到 5.5 秒”或“平均 Token 已降到 2300”作为已达成指标，因为当前实测没有达到这两个绝对目标。

## 6. 技术决策与权衡

本次优化的决策链如下：

1. 先用 Token 统计和节点延迟定位到三个串行模型调用以及重复邮件上下文。
2. 保留分类节点是为了让忽略类邮件快速结束；只合并非忽略邮件的意图和计划。
3. 模型保留自然语言理解，Python 接管步骤编号、准确会议时间、草稿信封和安全规则。
4. 使用配置开关保留基线，再以同一模型和数据集进行 A/B，而不是拿两个不同小样本比较。
5. 性能优化必须和质量指标一起看；本次分类和工具正样本准确率没有下降，审批与任务结果反而提高。
